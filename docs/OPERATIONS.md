# Bloom 運用ルール（ステージング → 本番）

日々の改修を「本番を止めない・壊さない」で回すための運用手順。
チャッピー相談（2026-08-08）で確定し、Laravel Cloud に実際に構築済み。

## 1. 環境（環境もDBも完全分離）

| 環境 | ブランチ | URL | DB |
|---|---|---|---|
| 本番 (production) | `kobayashi` | bloom-kobayashi-ycoeup.laravel.cloud（独自ドメイン bloom-fukuoka.com） | 本番DB `bloom`（Prod・20GB・常時稼働・7日バックアップ） |
| ステージング (staging) | `develop` | bloom-staging-ydnq6y.laravel.cloud | 別DB `bloom-staging`（Dev・5GB） |

- **ステージングDBに本番の顧客データを丸コピーしない**（必要なら匿名化データ）。
- env / secrets も完全分離。ステージングに本番DB接続情報を置かない。
- どちらも `Push to deploy` ON（対象ブランチへの push で自動デプロイ）。
- デプロイコマンド（両環境共通）：`php artisan migrate --force` ＋ config/route/view キャッシュ。

## 2. 1回の改修フロー

1. `feature/xxx`（または `develop`）で開発 → **ローカルで `php artisan test` を緑に**
2. `develop` へ反映 → **ステージングに自動デプロイ**
3. 開発者がステージングURLで主要導線を確認
4. 画面が変わる改修は **店長（確認者）がステージングで実務確認**
5. OK なら `develop` → `kobayashi` に反映 → **本番へ自動デプロイ**
6. 本番スモークテスト（§4）

> 店長・確認者は Git・本番操作・migration を触らない。役割は「ステージングでの確認」と「本番反映のGo判断」「不具合の報告」のみ。

## 3. 本番反映前チェック

- [ ] `git diff` に想定外の変更がない
- [ ] migration に **drop / rename / 型変更 / NOT NULL 追加 / 大量 UPDATE** が無いか確認（あるなら §5 の後方互換手順へ）
- [ ] ステージングで migration が実際に通っている
- [ ] （必要なら）`php artisan migrate --pretend` でSQLを確認
- [ ] 本番DBのバックアップ/スナップショットが取得可能な状態
- [ ] 営業ピーク中のDB変更は避ける

## 4. 本番反映後スモークテスト（5〜10分）

ログイン → 顧客表示・登録 → 来店/席 → 相談 → アフター → 権限（許可/非許可）→ エラーログ → `php artisan migrate:status`。

## 5. マイグレーションは「後方互換（additive）」が原則

**コードだけ前バージョンに戻しても壊れない状態**を保つのが、本番を止めない核心。

1. まず列・テーブルを **追加** する（既存を壊さない）
2. 新旧コードの両方で動く状態にする
3. データ移行
4. 後日の別デプロイで、不要になった旧列を削除

- ❌ 禁止：`migrate:fresh` / `migrate:refresh` / `db:wipe`、既存 migration の書き換え、drop 系を通常デプロイに混ぜる。
- `--force` は確認プロンプトを飛ばすだけで、破壊的 migration を安全にはしない。
- 「デプロイ履歴から戻せる＝DBも戻る」ではない（DBは自動では戻らない）。

## 6. ロールバック

- **コードの不具合**：Laravel Cloud のデプロイ履歴から直前デプロイへ戻す（ワンボタン）。
- **DB変更を伴う場合**：コードを戻すだけでは不十分なことがある。`migrate:rollback` は `down()` 次第でデータを失うため反射的に実行しない。§5 の後方互換設計で「戻さなくても壊れない」状態にしておく。

## 7. 最低限の約束（確認者＝店長向け）

- 本番で試さない。まずステージング。
- 本番反映ボタン・GitHub は開発者以外触らない。
- 確認は毎回同じチェックリスト（§4）。
- 不具合を見つけたら直そうとせず、**画面・時刻・操作**を報告。
- 営業時間中の大きな変更はしない。
